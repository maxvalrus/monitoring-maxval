# Производные SNMP-метрики

## Решение

Ручная SNMP-метрика может быть либо прямым OID, либо ограниченной производной
формулой. Это не общий язык автоматизации и не механизм зависимостей между
метриками: формула не может ссылаться на другую сохранённую метрику.

## Причина

Некоторые устройства, в частности Windows через HOST-RESOURCES-MIB, отдают
связанные счётчики в allocation units. Пользователю нужен один понятный
показатель, например свободная память в MiB, без списка технических исходных
OID и без их истории.

## Границы

- выражение безопасно разбирается AST без исполнения Python;
- доступны арифметика, `min`, `max`, `abs`, `round`, константы `KiB`/`MiB`/`GiB`
  и `oid("...")`;
- функции `hr_storage_*` сами запрашивают allocation unit, total и used для
  указанного индекса HOST-RESOURCES-MIB;
- максимум 16 уникальных исходных OID и 2 000 символов на формулу;
- исходные OID добавляются к существующему группированному SNMP GET, не
  создаются как скрытые метрики и не получают историю;
- результат хранится и участвует в существующих SNMP-порогах как обычная
  числовая метрика;
- ошибка одной формулы не меняет статус SNMP и не затрагивает другие метрики.

## Пример

`round(hr_storage_free_bytes(1) / MiB, 1)` возвращает свободное место
hrStorage index `1` в MiB.
