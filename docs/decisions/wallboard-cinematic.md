# TV: единый приборный стиль

Дата: 2026-09-09. Версия приложения не меняется.

По запросу пользователя Wallboard получил изолированный визуальный слой
`static/wallboard.css`: приборные корпуса объектов, семантические световые акценты,
единая типографика, графики в отдельной строке телеметрии и спокойное сканирование
площадок. Не создаются связи топологии, вымышленные показатели и новые health-состояния.
Обычные страницы не используют этот stylesheet. По следующему запросу пользователя
редактор схемы подключает его редакторский слой `.site-layout-page`: тот же фон,
приборные рамки значков, дыхание и оформление панели объектов. Цвет редактора
показывает размещение/конфигурацию, не выдуманный текущий health. Drag/drop, координаты,
масштаб 50–200%, CSRF и сохранение не меняются. Браузерный smoke проверяет сохранение
после перезагрузки и четыре размера окна. Оригиналы редактора перед этой правкой:
`backups/checkpoints/before-editor-hud/`.

В верхней телеметрии Wallboard отображаются агрегированное количество объектов и
запас scheduler; оба значения берутся из уже сформированного server snapshot без
дополнительного запроса к объектам. В шапке показаны версия приложения и крупные
часы, которые начинают отсчёт от серверного времени, полученного при рендеринге.
Количество приборов передаётся серверным CSS-классом, а не inline custom property:
действующая Content Security Policy запрещает inline-стили. Поэтому при работающем
scheduler все девять карточек телеметрии остаются в одной строке на экране 1920×1080.

Редактор схемы поддерживает локальное групповое перемещение: клик выбирает объект,
Ctrl/⌘-клик добавляет или убирает объект из набора, а drag выбранного элемента переносит
весь набор с сохранением относительного расположения. Клик по пустому месту снимает
выделение. Группа не является отдельной сущностью: в БД по-прежнему сохраняются только
обычные координаты каждого объекта.

По результату ручной проверки восстановлено заметное дыхание символов: спокойное
для OK, более частое для Warning/Offline/Critical. Анимируется только внутренний
значок, не сохранённые координаты или подписи. Возвращена пульсация иконок телеметрии,
усилен контраст сканирующей линии. Disabled/Off hours не пульсируют; системная
настройка reduced motion по-прежнему отключает эффекты. Браузерный smoke проверяет
не только наличие animation-name, но и изменение transform во времени.

По ручной оценке дыхание усилено одинаково в TV и редакторе: пик масштаба значка
1.14 вместо 1.09, свечение 12px вместо 9px. Периоды, подписи и координаты неизменны.
Проверки усиления: Ruff, 78 UI-тестов и браузерный smoke прошли. Concurrency-regression
использует реалистичное ожидание освобождения соединения БД вместо искусственного
таймаута SQLite 0.25 секунды; пять последовательных прогонов прошли. Рабочий CSS
проверен по хешу, readiness успешен; PWA cache обновлён до ui84.

Сохранены координаты и масштаб редактора, локальный TV-scale/pan, resize площадок,
ротация, разворачивание, выбор площадок, сервисы, окно событий и Critical-каскад.
Заголовок каждой площадки в общей TV-сетке можно перетащить на другую площадку: окна
меняются местами, а порядок сохраняется локально в браузере. Это не меняет серверный
порядок площадок, их настройки или схему объектов; в развёрнутом и rotation-режиме
перетаскивание намеренно отключено.
Через 15 секунд бездействия вторичные кнопки площадок приглушаются, но остаются доступны
мышью и с клавиатуры. `prefers-reduced-motion` отключает декоративную анимацию.

Найденные дефекты: обработчик Escape ссылался на отсутствующие переменные; периодическое
чтение `/wallboard` обновляло только Critical, оставляя схемы и телеметрию устаревшими.
Исправление повторно использует тот же GET раз в 15 секунд, без дополнительных запросов
к объектам. Существующие DOM-узлы и пользовательские параметры сохраняются. Изменение
health подсвечивается на объекте, восстановление — зелёным; реальные изменившиеся
значения и новые строки событий получают короткую подсветку. Ошибка чтения оставляет
последние данные и янтарный индикатор возле времени последнего успешного обновления.
Повторное создание страницы останавливает старый snapshot timer; скрытая вкладка не
выполняет snapshot GET. Backend расчётов, БД и scheduler не меняются.

## Проверка браузером

`scripts/check_wallboard_browser.py` использует синтетические данные в SQLite и
перехватывает browser HTTP локальным TestClient. Lifespan приложения не запускается:
рабочая БД, TLS и сетевые проверки не используются. Для запуска требуются Playwright,
Chromium и его системные библиотеки только в среде разработки, не в production:

```sh
.venv/bin/python -m pip install playwright
.venv/bin/python -m playwright install chromium
# При отсутствии системных библиотек: установка по согласованию с владельцем хоста.
# .venv/bin/python -m playwright install-deps chromium
.venv/bin/python scripts/check_wallboard_browser.py
```

## Откат

Перед изменениями сохранены оригиналы в локальном каталоге
`backups/checkpoints/wallboard-before-cinematic-20260909/`.
В копию не входят пароли, рабочая БД или `.env`. Этот каталог не является релизом.
Для отката именно этой правки (до дальнейшего редактирования соответствующих файлов):

```sh
cd /opt/monitoring-maxval
cp backups/checkpoints/wallboard-before-cinematic-20260909/base.html src/monitoring/templates/base.html
cp backups/checkpoints/wallboard-before-cinematic-20260909/wallboard.html src/monitoring/templates/wallboard.html
cp backups/checkpoints/wallboard-before-cinematic-20260909/app.js src/monitoring/static/app.js
cp backups/checkpoints/wallboard-before-cinematic-20260909/sw.js src/monitoring/static/sw.js
cp backups/checkpoints/wallboard-before-cinematic-20260909/routes.py src/monitoring/web/routes.py
docker compose build app
docker compose up -d --force-recreate --no-deps app
```

Новый `wallboard.css` после отката не подключается. Сохранённый `app.css` не менялся
в рамках этой правки. История, координаты и локальные настройки не удаляются.

## Итог QA

- Ruff: пройден; compileall `src`: пройден; JavaScript syntax check: пройден.
- Профиль UI: 78 passed; web: 43 passed; smoke: 33 passed.
- Дополнительный прогон web pages / responsive / PWA / packaging: 53 passed.
  Профили частично пересекаются; это не сумма уникальных тестов. Полный pytest не
  запускался согласно постоянному правилу разработки.
- Chromium: синтетическая страница на 1920×1080, 2560×1440, 1440×900 и 390×844;
  нет горизонтального overflow и пересечения текста телеметрии с графиками.
  Проверены сервисы, Escape, scale/focus, сохранение геометрии после обновления,
  реальное восстановление health из новой записи результата, десять Critical-карточек,
  недоступный snapshot и возобновление, reduced motion и светлая системная тема.
- Для Chromium библиотеки распакованы во временный каталог; системные пакеты хоста
  не изменялись. Playwright установлен только в development `.venv`, зависимости
  production не изменены.
- Рабочий Docker app обновлён, PWA cache `ui81`; `/health/ready` и выдача нового CSS
  проверены успешно. При повторном smoke обнаружено временное исчерпание SQLAlchemy
  pool: 15 idle-in-transaction соединений после SELECT сессий и частые GET `/wallboard`.
  После перезапуска readiness и статические ресурсы снова отвечают. Пользователю
  предложено переоткрыть старые TV-вкладки, чтобы загрузить исправленный JavaScript.
  Причина исчерпания pool не доказана окончательно; изменение настроек пула, auth
  или мониторингового backend в эту визуальную задачу не включалось.
  Впоследствии серверная причина воспроизведена и исправлена отдельно:
  [граница транзакции авторизации](auth-connection-lifetime.md).
