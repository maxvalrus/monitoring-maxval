# Разработка и релизы

## Источник решений

Изменения целей и границ вносятся в `PROJECT.md`. Архитектурные решения создаются в `docs/decisions/` по шаблону ADR. Фактические изменения версии попадают в `CHANGELOG.md`, план — в `docs/ROADMAP.md`.

## Правила изменений

1. Изменять только один смысловой модуль за раз, если задача не требует сквозного изменения.
2. Alembic используется и для создания схемы с нуля, и для обновления существующей
   рабочей базы. Перед изменением схемы обязательны forward-миграция, тест на пустой
   базе и проверка сохранения данных существующей установки. Docker volumes при
   обычном обновлении не удаляются.
3. Секреты, реальные адреса, пароли и SMTP-реквизиты не коммитятся.
4. Новая проверка реализует общий протокол и имеет тесты успеха и ошибки.
5. Любое изменение интерфейса проверяется минимум на ширине 1440 и 390 пикселей, включая
   вертикальные интервалы между соседними плашками, формами и кнопками: визуальные блоки
   не должны сливаться друг с другом.
6. Перед релизом проверяются светлая и тёмная темы.
7. Любое действие, которое остаётся в пределах текущей страницы (сохранение, удаление,
   ручная проверка, смена фильтра или пагинации), сохраняет текущую позицию прокрутки.
   Прокрутка допустима только при явном переходе пользователя либо при намеренном фокусе
   на поле или блоке, требующем внимания. Новый POST-маршрут с `return_to` обязан
   разрешать фактический путь вызывающей страницы, иначе фоновая форма не должна
   перенаправляться на другой экран.
8. Версия меняется только в `src/monitoring/__init__.py`; `pyproject.toml` получает её оттуда автоматически.
9. Для локального запуска полного pytest на Debian/Ubuntu обязателен пакет
   `fonts-dejavu-core`: PDF-export тест и генератор отчётов используют
   `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` для кириллицы. Рекомендуется
   также `fontconfig` для проверки через `fc-match`. Установка:

   ```bash
   sudo apt-get install -y fonts-dejavu-core fontconfig
   ```

   Runtime Docker-образ уже устанавливает `fonts-dejavu-core` в `Dockerfile`; это
   требование относится к локальной среде разработки и QA на хосте.
9. Для каждого нового релизного архива отдельно создаётся готовый `.env` со свежими
   случайными `POSTGRES_PASSWORD` и `MONITORING_SECRET_KEY`. Файл добавляется только в
   ZIP, не сохраняется в Git и не переносится в следующий релиз без замены секретов.
   Этот `.env` предназначен для чистой установки; при обновлении сохраняется рабочий
   `.env`, чтобы не потерять доступ к базе, сессиям и зашифрованным SMTP-настройкам.
   Готовая конфигурация рассчитана на HTTP внутри доверенной сети/VPN: Host разрешён
   маской `*`, `MONITORING_SESSION_COOKIE_SECURE=false`; для внешнего HTTPS Host
   ограничивается, а `MONITORING_SESSION_COOKIE_SECURE` меняется на `true`.
   В файл включаются только обязательные параметры запуска; редактируемые настройки
   приложения и значения с безопасными встроенными defaults не дублируются.
10. Краткая инструкция каждого нового релиза сразу после команд запуска содержит
   отдельную необязательную команду создания демонстрационных данных:

   ```bash
   sudo docker compose exec app python scripts/seed_demo.py
   ```

   Пользователю не должно требоваться искать эту команду в README, полном руководстве
   или истории чатов.
11. При выдаче релиза пользователю предоставляются две отдельные соседние ссылки:
    релизный ZIP и краткая инструкция этой же версии. Инструкция также остаётся внутри
    архива и репозитория.
12. Релизный ZIP — чистый самостоятельный каталог только своей версии. В него входят
    исходный код, Docker/Compose-файлы, миграции, шаблоны, необходимые статические
    файлы, документация, краткая инструкция текущей версии и один новый `.env`. В него
    не входят предыдущие ZIP и инструкции предыдущих версий, локальные рабочие каталоги,
    `.git`, `.agents`, `.codex`,
    кэши, логи, резервные копии, реальные TLS-файлы, рабочий `.env` и прочий
   внутренний материал. Состав архива проверяется автоматически до выдачи.
    Для сборки используется `python scripts/build_release.py <версия>`.
13. В интерфейсе используются два разных паттерна галочек. Компактные карточки
    `push-option` предназначены для вторичных параметров в составе формы, например
    STARTTLS и очистки сохранённого SMTP-пароля. Крупные самостоятельные переключатели
    `setting-toggle-control` используются только для важных настроек, меняющих режим
    работы подсистемы: например «Использовать SMTP», HTTPS или SNMP. Не смешивать эти
    паттерны без явной причины.

## Стратегия автоматических тестов

Подробное правило и профили находятся в `docs/TESTING.md`.

Во время разработки не запускается полная регрессия после каждой мелкой правки: достаточно
`smoke` и тестов затронутого модуля.

```bash
python scripts/test_suite.py smoke
python scripts/test_suite.py module <модуль>
```

Полный набор запускается только перед созданием релиза, после упаковки на содержимом
распакованного финального ZIP либо по явной команде пользователя. Тесты сгруппированы
по функциональным областям; новый файл с номером релиза вместо назначения модуля не
создаётся.
Искусственного лимита на число тестов нет.

## Минимальная проверка перед релизом

```bash
ruff check .
python -m compileall -q src tests
python scripts/test_suite.py full
docker compose config >/dev/null
docker compose build app
docker compose run --rm app alembic upgrade head
curl --fail http://127.0.0.1:8000/health/ready
```

Дополнительно вручную проверяются:

- наличие готового `.env` в релизном ZIP, совпадение пароля в
  `MONITORING_DATABASE_URL` и `POSTGRES_PASSWORD`, уникальность сгенерированных секретов;
- отсутствие `.env` в Git и отсутствие его содержимого в выводе тестов и журнале;

- вход и выход администратора и наблюдателя;
- расположение переключателя темы в правом верхнем углу карточки авторизации на
  настольной и мобильной ширине;
- расположение переключателя темы в строке пользователя рядом с кнопкой выхода после
  авторизации, без наложений и вертикального растягивания на телефоне;
- запрет изменяющих запросов для наблюдателя и запросов без CSRF-токена;
- защита последнего активного администратора;
- главная, площадки, объекты, настройки, пользователи и аудит на компьютере;
- формы создания и редактирования внутри карточек: все поля и кнопки остаются в
  границах карточки без горизонтальной прокрутки;
- дополнительные галочки объекта собраны вместе, а основная кнопка формы находится
  справа внизу на компьютере и планшете и становится полноширинной на телефоне;
- кнопки фильтров и форм добавления сгруппированы справа, не расходятся по случайным
  строкам при переносе и становятся полноширинными на телефоне;
- фильтры и пагинация состояния, площадок, объектов, инцидентов, пользователей и аудита на
  первой, промежуточной и последней страницах;
- фильтры и сортировка аудита с сохранением параметров в URL;
- фильтр объектов «Исключить из уведомлений» с сохранением в URL, сортировке и
  пагинации;
- фильтр объектов «Избранное» со значениями «Все / Да / Нет» с сохранением в URL,
  сортировке и пагинации;
- глобальная отметка избранного доступна для изменения только администратору,
  защищена CSRF и записывается в аудит;
- выключенная кнопка избранного выглядит нейтрально, а включённая заметно выделена и
  сообщает состояние через `aria-pressed`;
- избранные объекты располагаются перед обычными после фильтрации, но до серверной
  пагинации состояния;
- отказ при повторном добавлении объекта с полностью совпадающими параметрами;
- сортировка по каждому содержательному заголовку всех таблиц в обоих направлениях;
- отсутствие горизонтальной прокрутки таблиц на ширинах 1440, 1024, 900, 760 и 390
  пикселей;
- нормальная высота поля поиска после вертикальной перестройки фильтров на iPhone и
  планшете;
- компактная ширина значков состояния и единая сетка подробностей аудита на планшете;
- появление доступной кнопки «Наверх» после прокрутки без перекрытия элементов и с
  учётом безопасной области iPhone;
- однострочные заголовки колонок и компактные кнопки действий на 1440 пикселях;
- раскрытие редакторов площадки и объекта на полную ширину таблицы;
- табличный список пользователей, его полноширинный редактор и независимая сортировка
  пользователей и активных блокировок;
- явная дата и время последней проверки каждого объекта на странице состояния;
- кнопка ручного обновления доступна только администратору, запускает один фоновый
  обход и не создаёт параллельный повтор при двойном нажатии;
- ручная проверка создаёт результаты и инциденты тем же путём, что планировщик, и не
  проверяет объекты отключённых площадок;
- автообновление состояния по умолчанию выключено, запоминается в браузере и повторяет
  текущий GET-запрос раз в 60 секунд без запуска сетевых проверок;
- подписи «Автообновление страницы» и «Опросить объекты» однозначно разделяют
  перечитывание экрана и запуск сетевых проверок;
- автообновление сохраняет фильтры и страницу, не мешает ручной кнопке и проверяется в
  сценарии длительного отображения на телевизоре;
- соответствие всех дат выбранному в веб-разделе настроек часовому поясу и наличие его
  обозначения рядом со временем;
- смена часового пояса администратором без изменения `.env` и перезапуска контейнера;
- отсутствие `MONITORING_DISPLAY_TIMEZONE` и необязательных строк в готовом `.env`;
- быстрый фильтр инцидентов по каждому типу объекта с сохранением выбора в пагинации;
- совместные быстрые фильтры инцидентов по типу объекта и состоянию «Открытые» или
  «Закрытые», включая сброс и переходы между страницами;
- загрузка CSS и JavaScript с параметром текущей версии после обновления;
- удаление объекта, пустой площадки, всех объектов площадки, одного и всех инцидентов;
- отключение объекта непосредственно из карточки инцидента без автоматического
  удаления или закрытия самого инцидента;
- единая цветовая семантика статусов: штатный/активный — зелёный,
  отключённый/аварийный — красный, предупреждение — жёлтый;
- нейтральные элементы раскрытия редакторов и заметные названия сущностей во всех
  адаптивных таблицах;
- активный пункт верхнего меню имеет `aria-current="page"` и короткую полоску под
  текстом без фонового прямоугольника;
- снятие конкретной активной блокировки и наличие соответствующих записей аудита;
- минимальный пароль первого администратора длиной 8 символов;
- автоматическая установка портов HTTP/HTTPS и скрытие порта ICMP;
- сохранение параметров фильтров и размера страницы в URL и после изменения записи;
- справка по проверкам на компьютере и телефоне;
- TCP, HTTP, HTTPS и ICMP на успешном и неуспешном сценариях;
- RTSP на ответах 200, 401 и ошибке потока, без загрузки видео;
- фоновая отправка форм сохраняет CSRF, прокрутку и открытый редактор, а без
  JavaScript остаётся обычный серверный POST;
- всплывающие уведомления об успехе и ошибке не перекрывают интерфейс телефона;
- показатели CPU, памяти, диска, аптайма, сетевых байтов и пакетов отображаются без
  установки агента;
- история показателей портала очищается по отдельному сроку хранения;
- отчёты за 24 часа, 7, 30 и 90 дней корректно агрегируют объекты и площадки;
- график и история отдельного объекта доступны администратору и наблюдателю;
- PWA устанавливается, service worker имеет область `/` и не кэширует закрытый HTML;
- удаление только просроченной истории по `history_retention_days`;
- создание резервной копии, `pg_restore --list` и контрольное восстановление на
  отдельной тестовой базе;
- загрузка через UI и восстановление в отдельную PostgreSQL обоих типов `.mxbak`:
  конфигурационного с очисткой эксплуатационных данных и полного с их сохранением;
- портретная и альбомная ориентации телефона;
- автоматическая, светлая и тёмная темы;
- открытие одного инцидента после настроенного числа ошибок и его закрытие после `up`;
- отсутствие повторных автоматических писем по одному событию инцидента;
- отсутствие автоматических уведомлений при общем выключателе или флаге объекта
  «Исключить из уведомлений», при сохранении результатов и инцидентов;
- отправка email только когда общий переключатель включён, SMTP-канал включён и объект
  не исключён;
- выключение SMTP-канала сохраняет реквизиты и блокирует автоматические письма;
- работа ручного тестового SMTP-письма независимо от общего выключателя;
- сохранение SMTP без повторного ввода пароля и без изменения зашифрованного значения;
- сохранение, отображение и тестовая отправка нескольким SMTP-получателям с разными
  разрешёнными разделителями;
- тестовая отправка SMTP при выключенных автоматических уведомлениях, без вывода пароля
  или исходного ответа SMTP-сервера в интерфейс, журнал или diff;
- favicon и логотип на страницах до и после авторизации;
- запуск с пустой базой;
- создание полной схемы на пустой базе;
- чистый перезапуск после удаления тестового тома PostgreSQL;
- отсутствие секретов и реальных адресов в журнале и diff.

## Обновление одного модуля

Модули проверок можно поставлять независимыми Python-пакетами через entry points. После
обновления такого пакета перезапускается процесс приложения или будущий worker. Если
модуль меняет схему данных, Alembic-переход проверяется на пустой и существующей базе;
данные рабочей установки должны сохраняться.
