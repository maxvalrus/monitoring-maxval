# Состояние проекта «Мониторинг Maxval»

Дата актуализации: 2026-09-12.

## Версия и данные

- Текущая рабочая и якорная версия: **0.8.5**.
- Alembic head: **0036**.
- Схема поставляется одной базовой миграцией `0036_baseline_0_8_5.py`; она предназначена
  для чистой установки 0.8.5.
- Рабочие данные, Docker volumes, `.env` и TLS сохраняются при обычном обновлении.
- Configuration и full backup восстанавливаются только при точном совпадении версии
  приложения.
- Релиз собирается только по явной команде пользователя с номером версии.

## Текущий состав

Monitoring Maxval — компактный внутренний мониторинг доступности, а не аналог Zabbix.
В состав 0.8.5 входят площадки и графики работы, основная и secondary-проверки,
инциденты, отчёты доступности, SMTP/PWA Push, пользователи, аудит, внутренний личный чат,
портальная телеметрия и адаптивный интерфейс.

SNMP v1/v2c опционален для объекта и включает System OID, ручные OID и формулы,
IF-MIB-интерфейсы, расходники Printer-MIB, UPS-MIB/APC PowerNet, историю и пороги.
Все специализированные данные используют существующий SNMP polling, Target Health,
incident flow и backup subsystem.

Wallboard `/wallboard` визуализирует сохранённые схемы площадок на TV: несколько
площадок, локальные размеры/порядок/панорамирование, масштаб, сервисные LED,
плавающие события, Critical-каскад и HUD-телеметрию. Он не создаёт scheduler,
топологию сети или отдельную health-модель.

## Эксплуатационные правила

- HTTP работает по умолчанию; Caddy обслуживает опциональный HTTPS без HSTS.
- Сертификаты и private keys хранятся вне БД; TLS-manager применяет только
  проверенный candidate и поддерживает rollback.
- Перед обновлением создаётся и проверяется резервная копия. `docker compose down -v`
  не используется при обычном обновлении.
- Реальные пароли, private keys, адреса и персональные данные не хранятся в репозитории
  и документации.
